# 13 · Quality assurance

**Why it matters:** Testing catches problems before visitors do. Automated checks guard every change; manual tests on real devices catch what tools miss. Guide: Phase 5.

Detail: `reference/google-search/` notes.

Scope: browser and device coverage, automated tests, audits, content QA, defect severity, definition of done. CI template: [`ci/quality.yml`](../templates/ci/quality.yml).

Last verified: 2026-10

| ID | Level | Rule | Verify |
|---|---|---|---|
| QA-01 | MUST | Use Baseline "Widely available" web features freely, and newer features only with a fallback. Test the last 2 versions of Chrome, Edge, Firefox and Safari (macOS and iOS), plus Chrome on Android. | Test matrix |
| QA-02 | MUST | Test viewports 360, 390, 768, 1024, 1440 and 1920 px: no overflow, overlap or clipped content (UX-05). | Screenshots per template |
| QA-03 | MUST | CI runs static checks on every change: HTML validation (TEC-02), lint and format (TEC-24), link check (SEO-25). | CI log |
| QA-04 | MUST | Lighthouse CI runs on key templates, median of 3 runs, with assertions for performance (PRF-02), accessibility (A11Y-23) and SEO. Failing assertions block the merge. | [`lighthouserc.json`](../templates/ci/lighthouserc.json) |
| QA-05 | MUST | Every critical flow (contact, checkout, sign-up, login) has end-to-end tests in Chromium, Firefox and WebKit. Tests use role or label locators and test data, and never real endpoints that send email or take payment. | E2E report |
| QA-06 | SHOULD | Key templates have visual regression snapshots taken in a pinned environment (fixed OS and browser image), reviewed on every UI change. | Snapshot diff |
| QA-07 | MUST | Before launch, test manually on a real iOS phone and a real Android phone, with throttled network (slow 4G) and CPU. The Back button returns to the previous page. | Test protocol |
| QA-08 | MUST | Before launch, crawl the full site: status codes, canonicals, titles, descriptions, H1, structured data, internal links, sitemap vs. crawl. | Crawl export |
| QA-09 | MUST | Content QA: no placeholder text (`lorem`, `TODO`, `example.com`, `XXX`, `REPLACE`), no empty `<img src>`, placeholder image hosts (`placehold`, `picsum`) or grey stand-in boxes, no sample names or numbers (`John Doe`, `Acme`, `Your Name`, `[X]`, `555-`, `123,456`), no `href="#"`, empty handlers or buttons without an action, no unbuilt features in the navigation, no indexable test pages, spelling checked, every link, phone number and email address works, legal pages final. | Grep build output; crawl |
| QA-10 | MUST | Defect severity: **P0** site down, legal or security breach. **P1** core flow broken or a MUST rule failing. **P2** SHOULD rule failing or noticeable issue. **P3** cosmetic. P0 and P1 block launch. | Issue tracker labels |
| QA-11 | SHOULD | Definition of done for each change: the affected rule IDs are verified, CI is green, the preview is checked at 390 and 1440 px, and the console shows no errors. | PR template |
| QA-12 | SHOULD | Visual QA compares implementation and design at identical viewports and states, and records every deviation. | QA protocol |
| QA-13 | COULD | Dynamic endpoints are load-tested for the expected peak (e.g. a launch campaign). | Load test report |
| QA-14 | SHOULD | Visual QA and screenshot tests run on the production build (`build` plus `preview`), not the dev server; screenshots are taken after entrance motion settles (or under reduced-motion emulation), full-page from the top, and each file is opened to confirm it is complete. | Build command recorded in the PR; screenshot review |
| QA-15 | SHOULD | Pre-launch security review: list every entry point (forms, APIs, uploads, auth routes, webhooks, redirects, admin, WebSockets) and tick each against SEC-08 to SEC-46; anything unreviewed is recorded as "not covered", never as passed. P0/P1 security findings are re-checked by a second person who tries to refute them. | Attack-surface inventory in the audit report |
| QA-16 | COULD | [house] The real-iPhone test (QA-07) includes Low Power Mode, which can suspend autoplay video and animation: the poster fallback shows and no content depends on motion. | iPhone with Low Power Mode on |
