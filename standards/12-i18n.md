# 12 · Internationalization

**Why it matters:** A correct multilingual setup shows each visitor the right language and stops language versions from competing with each other in search. Guide: step 30.

Detail: `reference/google-search/` notes.

Scope: multilingual and multi-regional sites: URL structure, hreflang, localization, formats, right-to-left scripts. Applies only to sites with more than one language or market.

Last verified: 2026-10

| ID | Level | Rule | Verify |
|---|---|---|---|
| I18N-01 | MUST | Each language or market has its own URL. Default: subdirectories (`/de/`, `/en/`). Use ccTLDs only with a strong local presence (house choices: subdirectory default, ccTLD limit). Never select the language by cookie, parameter or IP alone. | URL map |
| I18N-02 | MUST | No automatic redirects by IP or `Accept-Language`. A visible switcher links to the equivalent page in the other language, not to its home page. | Test with a VPN and with browser language changed |
| I18N-03 | MUST | hreflang: every version lists all versions including itself, reciprocally, with absolute URLs and `x-default`. Codes are ISO 639-1 language, optionally with an ISO 3166-1 alpha-2 region (`de-AT`; not `en-UK`, `es-419`, `EU` or a region alone; `zh-Hans` is fine). Several locales of one language also get a generic language URL (`en`). In HTML, tags sit in a well-formed `<head>`, one per version, with no other attributes such as `media`. Use one method only: HTML, HTTP header or sitemap. Template: [`head.html`](../templates/head.html). | Crawler hreflang report |
| I18N-04 | MUST | Each language version is self-canonical. Never canonicalize across languages. Same-language regional variants with near-identical body text (`en-US`/`en-GB`; `example.de/` vs. `example.com/de/`) are duplicates: choose a preferred URL, canonicalize to it and keep hreflang. | Crawler |
| I18N-05 | MUST | The `lang` attribute matches the content language (A11Y-05), and `og:locale` is set. | Source |
| I18N-06 | MUST | Everything is localized: navigation, UI text, title and description, alt text, structured data, error pages and legal pages. No mixed-language pages: one language per page for content and navigation, no side-by-side translations. The `<title>` uses the page's language and script (no transliteration). | Crawl per language folder |
| I18N-07 | SHOULD | Localize rather than translate: keyword research per market, local examples, currency, units, payment methods, phone formats and trust signals, reviewed by a native speaker. | Market review |
| I18N-08 | SHOULD | Dates, numbers, currencies, units and lists are formatted per locale with the `Intl` APIs. Time zones are explicit. | Code review |
| I18N-09 | SHOULD | Layouts tolerate 30–40 % longer text and other scripts (font subsets per script, PRF-10). | Pseudo-localization test |
| I18N-10 | MUST | Right-to-left languages use `dir="rtl"` on `<html>`, CSS logical properties (`margin-inline-start`, not `margin-left`), mirrored directional icons, and `<bdi>` or `dir="auto"` to isolate mixed-direction text. | RTL visual QA |
| I18N-11 | SHOULD | Source strings live outside the templates, with a translation memory and glossary. Machine translation is never published without human review (CON-09). | Workflow |
| I18N-12 | SHOULD | Search performance and rankings are reviewed per language folder and market (MSR-24). | GSC page filter per folder |
| I18N-13 | COULD | Markets with a physical presence get their own local entity signals: Business Profile, local phone and address. | Profiles |
| I18N-14 | SHOULD | Country targeting uses URL structure and hreflang. Page language is read from visible content, not `lang`, hreflang or the URL. `.io`, `.co`, `.ai`, `.me`, `.tv`, `.eu`, `.asia` and other generic TLDs do not geotarget. `geo.position` and `distribution` meta tags are ignored. | URL map; GSC page filter per folder |
| I18N-15 | SHOULD | robots.txt and robots meta are identical in every locale. Googlebot is never geo-blocked unless users from that country are blocked too (it crawls from US and non-US IPs). Locale-adaptive content is checked with URL Inspection. | Per-locale robots.txt diff; URL Inspection |
