# 02 · Brand & design

**Why it matters:** Visitors judge credibility in seconds, mostly from visual quality and consistency. A documented brand, a golden-ratio design system and tokens keep every page consistent, handcrafted rather than generic, and cheap to change. Guide: steps 11–13.

Detail: `reference/google-search/` notes.

Scope: design intake, identity, icon and animation sourcing, tokens (states, elevation, borders, composite typography, themes, governance), color, typography, hierarchy, spacing, shape, buttons, links, inputs, icons, data visualization, dark and forced-colors modes, motion, imagery, brand assets, handoff. Grid, breakpoints, devices and page structure: [`15-layout-responsive.md`](15-layout-responsive.md). Component catalogue: [`16-components.md`](16-components.md). The brand spec lives in [`DESIGN.md`](../templates/DESIGN.md), the values in [`tokens.json`](../templates/tokens.json). Perception and usability principles: [`14-ux-psychology.md`](14-ux-psychology.md).

Last verified: 2026-11

## Golden-ratio system (φ ≈ 1.618)

| Scale | Values (base 16 px) |
|---|---|
| Type, step √φ ≈ 1.272 | 12.6 small · caption · H6 · **16 body** · H5 · 20.4 H4 · lead · 25.9 H3 · 32.9 H2 · 41.9 H1 · 67.8 display (two steps above H1) |
| Space, step φ | 4 · 6 · 10 · 16 · 26 · 42 · 68 · 110 · 178 px |
| Radius, step φ | 6 · 10 · 16 · 26 px · pill |
| Layout split | 61.8 % / 38.2 % (content/aside, text/image, hero columns) |
| Line height | body 1.6 · headings 1.1–1.25 |

## Intake, identity, color

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-13 | MUST | Before any UI work, ask the client and record the answers in `DESIGN.md`: color palette (or offer 2–3 suggested palettes derived from brand, industry and audience, each contrast-checked), style direction (e.g. minimal/simple, modern translucent, bold/expressive, editorial, classic/corporate, playful), light, dark or both, density (airy or compact), 2–3 references the client likes and 1 they dislike (with why), what must stay untouched, 8–12 facts only this client has (name, place, materials, real numbers) and 2–3 personality words (not "clean", "modern", "premium"). Building starts only once answered or explicitly delegated. | `DESIGN.md` intake filled |
| DES-01 | MUST | `DESIGN.md` documents the brand for people and AI agents: intake answers (DES-13), positioning (STR-03), personality, voice and tone, logo use, color roles, typography, imagery, icons, motion and glossary. | File exists and is current |
| DES-02 | MUST | Design tokens live in `tokens.json` (W3C DTCG format) in three tiers: primitive → semantic → component. Components use only semantic or component tokens, and code consumes them as CSS custom properties (TEC-04). | Token build; grep CSS for raw hex values |
| DES-14 | MUST | [house] Palette structure, 60-30-10: about 60 % primary (the brand color and its tints on large surfaces), 30 % secondary (a supporting color for sections, cards and illustrations) and 10 % accent (reserved for the primary call to action and key highlights). A 9–10 step neutral scale for text, borders and backgrounds and semantic status colors sit outside the ratio. No second accent competing for attention. | Token review; screenshot color audit |
| DES-27 | MUST | Text color roles exist as semantic tokens: `text.default`, `text.secondary`, `text.muted`, `text.disabled`, `text.inverse`, `text.on-accent`, `text.link`, `text.link-visited` (if used) and `text.status.*`. Muted text never carries essential content. Each role is paired with its allowed backgrounds (DES-03). | Token review |
| DES-49 | SHOULD | Muted and secondary text use opaque tokens, never `opacity` or alpha on text, so contrast stays measurable (WCAG 1.4.3). | Grep `opacity` on text selectors; contrast of computed colors |
| DES-50 | COULD | [house] Tint ramps are built in a perceptual space (OKLCH, CSS Color 4) with chroma reduced near the lightness ends; the method is recorded in the token `$description`. Display type sets line height 0.95–1.1, letter-spacing ≥ −0.04 em, size ≤ 6 rem, ≥ 3× body on marketing pages, with no ascender/descender collision at 360 px. | Token file; screenshots at 360 and 1440 px |
| DES-03 | MUST | Every text/background pairing defined in tokens meets A11Y-07. Hover, focus, error, success and warning states have their own tokens. Dark mode, if offered, overrides the same semantic tokens. | Contrast check of token pairs |

## Typography, spacing, layout

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-04 | MUST | Typography follows the golden-ratio scale: body 1 rem (16–18 px), H4 1.272 rem, H3 1.618 rem, H2 2.058 rem, H1 2.618 rem on desktop, one step smaller on mobile, fluid via `clamp()`. At most 2 families. Body line-height ≈ 1.6, headings 1.1–1.25, 45–75 characters per line (aim for ≈ 66; ≥ 35 on mobile, LAY-04). One H1 per page, no skipped heading levels (A11Y-04). | Computed styles at 360 and 1440 px |
| DES-15 | SHOULD | Headings use weight 600–700, body 400, labels 500–600. Large headings get −0.01 to −0.02 em letter-spacing. Sentence case; no all-caps beyond short labels. `text-wrap: balance` for headings, `pretty` for body. | Computed styles |
| DES-24 | MUST | Every type role has a token with size, weight, line-height and letter-spacing: display, H1 (the page title), H2–H4 per DES-04, H5 1 rem/600, H6 0.786 rem/600, eyebrow/overline 0.786 rem/600 with +0.06–0.1 em tracking (stored as a rem dimension, DTCG) (all-caps allowed, ≤ 3 words), lead 1.272 rem/400 at line-height 1.5, body, small and caption 0.786 rem, label 0.786–1 rem/500–600, code (mono family), footer and legal text 0.786–0.875 rem. Nothing renders below 12.6 px (0.786 rem). Subheadings are real headings in the outline (A11Y-04); eyebrows and taglines are not. | Token file; computed styles |
| DES-25 | MUST | Vertical rhythm: the space above a heading is at least φ times the space below it (H2 42/16 px, H3 26/10 px, H4–H6 26/6 px). Paragraphs are spaced 1 em, list items 6–10 px, figures and tables one φ step more than paragraphs. The first child of a container has no top margin. Use logical properties (`margin-block`). | Computed styles; overlay review |
| DES-26 | SHOULD | Typographic details: tabular numerals (`font-variant-numeric: tabular-nums`) in tables, prices and counters; no justified text; `hyphens: auto` with the correct `lang` in narrow columns, never in headings; locale-correct quotes, apostrophes and dashes; non-breaking space between number and unit; headings wrap at ≤ 35 ch; link underlines with `text-underline-offset` 0.15–0.25 em; `font-synthesis: none` so the browser never fakes missing weights or italics. | Computed styles; copy review |
| DES-05 | MUST | Spacing uses only the φ scale. Space inside a group is at least one φ step smaller than space between groups (PSY-02). | Token file; spacing audit |
| DES-16 | MUST | Layout: 12-column grid on desktop (columns per tier: LAY-02) with content-driven breakpoints, container max 1200–1280 px, text column ≈ 66 ch, asymmetric splits at 61.8/38.2, section padding 68–110 px on desktop, 68 on tablet and 42 on mobile (LAY-05), shared alignment lines, whitespace instead of decoration. | Grid overlay at 390 and 1440 px |

## Hierarchy, emphasis, alignment

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-28 | MUST | Emphasis budget: at most three emphasis levels per section (primary, secondary, tertiary), adjacent heading levels differ by at least one type step, one focal point per view (PSY-03). Bold marks ≤ 10 % of running text, italics only for titles and terms, underline only for links (DES-19), all-caps only for labels (DES-24). The accent stays reserved for the primary action (DES-14). | Squint test; screenshot review |
| DES-29 | SHOULD | Alignment: running text is start-aligned (left, or right in RTL, I18N-10). Centered text only for headings and blurbs of ≤ 3 lines. One alignment axis per section. Numbers in tables align to the end (CMP-04). | Screenshot review |

## Shape, buttons, links, inputs

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-17 | MUST | Shape: one radius family from the φ scale applied by role (controls 10, cards 16, large panels 26, tags pill); nested radius = outer radius − padding. One elevation system (≤ 3 shadow levels, or borders), not mixed at random. One icon set with one stroke width, sized 1–1.272 em of the adjacent text. | Component audit |
| DES-18 | MUST | Buttons come in three tiers only: primary (filled accent), secondary (outline or tonal), tertiary (text). Min height 44 px, horizontal padding 16–26 px from the φ scale, verb label (UX-15) at 1 rem/600, all states (DES-06) and a visible focus ring. At most one primary per view (UX-06). Icon-only buttons have an accessible name. | Component audit; keyboard test |
| DES-19 | MUST | Links in running text are underlined (or carry another non-color cue) and differ from body text in color. They have hover and focus-visible states, and say when they open a new tab. Link text names the target (A11Y-15). Links navigate; buttons act. | Page review |
| DES-20 | SHOULD | Inputs: label above the field, 44 px height, one border style, focus ring in the focus token, error state with icon and text (A11Y-17). A placeholder never replaces the label. | Form review |
| DES-33 | SHOULD | Icons: one set on a 24 px grid (sizes 16, 20, 24, 32), colored with `currentColor`. Decorative icons are `aria-hidden`; standalone icons have an accessible name (A11Y-06). Only universally known icons (search, menu, close, home, cart) stand without a text label. Directional icons mirror in RTL (I18N-10). | Component audit |
| DES-51 | SHOULD | SVG parts that scale or rotate set `transform-box: fill-box` and an explicit `transform-origin`; motion starts from its physical anchor (a menu from its trigger, a popover from its arrow). | Chrome and Safari check; grep SVG transforms |
| DES-42 | MUST | Icon sourcing: one library per site from [`reference/assets/`](../reference/assets/README.md), imported icon by icon as inline SVG (tree-shaken); no icon fonts, no full-set bundles, no mixing sets. Size and stroke come from `iconSize`/`iconStroke` (DES-33). The library and license are recorded in the third-party inventory (TEC-20) and the handover (TEC-27). | Bundle analyzer; inventory entry |
| DES-06 | MUST | Component inventory: every component documents its states (default, hover, focus-visible, active, disabled, loading, error, empty) and its responsive behavior. | Component library or `DESIGN.md` |
| DES-07 | SHOULD | Each component is built once and reused, in the design library and in code. No one-off variants without review. | Library usage report |

## Tokens, modes, data visualization, handoff

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-30 | MUST | The token set is complete. Besides color, type, space and radius, it defines: breakpoints (LAY-01), content widths (LAY-03), z-index (base 0 · raised 10 · dropdown 100 · sticky 200 · overlay 300 · modal 400 · toast 500 · tooltip 600), border widths (1 and 2 px), focus ring (2–3 px width, 2 px offset, `color.focus`), shadow levels (≤ 3, DES-17), scrim opacity (0.5–0.7), motion durations and easings (DES-08), aspect ratios (1:1 · 4:5 · 4:3 · 3:2 · 16:9 · φ 1.618:1) and icon sizes (DES-33). Components use no raw values (DES-02). | Token file review; CSS grep |
| DES-31 | SHOULD | Forced-colors mode (`@media (forced-colors: active)`) stays usable: buttons, cards and inputs keep visible borders (transparent borders, not only backgrounds), focus stays visible, icons use `currentColor`, and no information lives only in background images or shadows. | Windows contrast theme or DevTools emulation |
| DES-32 | SHOULD | Dark mode, if offered (DES-12): surfaces get lighter with elevation instead of relying on shadows, accent and status colors are adjusted to pass A11Y-07 on dark surfaces, no pure black (#000) behind long text, logos and images have dark-safe variants, and every component is checked in both themes. | Screenshots in both themes |
| DES-34 | SHOULD | Charts: a categorical palette of ≤ 8 colors that stays distinguishable with color-vision deficiencies, marks ≥ 3:1 against the background (A11Y-07), meaning never in color alone (direct labels, patterns or shapes), direct labels over legends, bar axes starting at zero, and a text summary or data table (A11Y-06). The chart type follows the data (trend: line; comparison: bar; part of a whole: bar, or a pie of ≤ 5 slices); the title states the finding and the subtitle the data, place and period; one highlight color, the rest neutral. | Color-blindness simulation; screen reader check |
| DES-35 | SHOULD | Handoff: design files use variables and styles named and structured exactly like `tokens.json`. Tokens flow from one source into CSS by a build step; nobody copies values by hand. | Compare design variables with the token file |
| DES-36 | MUST | State tokens: every interactive token has hover, pressed, focus, disabled and (where it applies) selected values. A hover effect combines at most two of: one color step, a state layer (hover ≈ 8 %, pressed ≈ 12 % opacity), a lift ≤ 2 px, a scale ≤ 1.02, one shadow level up, an underline change. Timing comes from the transition tokens (DES-08); hover effects are gated by LAY-08 and never the only state cue. | Component audit in all states |
| DES-37 | MUST | Elevation: `shadow` tokens for three levels plus an inset, each tied to one use (level 1 card, level 2 dropdown and popover, level 3 dialog and toast) and matched to z-index tokens (DES-30). No other shadows. Dark mode raises surfaces by lightness instead (DES-32). | Token file; CSS grep for raw `box-shadow` |
| DES-38 | MUST | Borders and outlines: composite `border` tokens (color, width, style) for default, subtle, divider and input states (default, hover, focus, error, disabled). The focus outline is a token (2 px solid, 2 px offset, inset variant for clipped containers) that reaches 3:1 against every surface it appears on (A11Y-07). | Token file; contrast check |
| DES-39 | SHOULD | Every type role (DES-24) is one composite `typography` token (family, size, weight, line height, letter spacing). Fluid roles record their mobile and desktop sizes for `clamp()` (LAY-04). Components reference the composite, not single properties. | Token file review |
| DES-40 | SHOULD | Themes override semantic tokens only, never primitives or components: a dark set if dark mode is offered (DES-12, DES-32), an optional high-contrast set, and a documented forced-colors mapping to CSS system colors (DES-31). Every semantic color exists in every theme. | Token build per theme; contrast check per theme |
| DES-41 | SHOULD | Token governance: names follow `tier.category.role.state` in lowercase kebab case; semantic and component tokens carry a `$description`; retired tokens stay one release with `$deprecated` naming the replacement; changes are logged in `DESIGN.md`. A validator checks references, types, units and contrast pairs in CI. | `scripts/check_tokens.py` |

## Handcrafted look, style directions, motion

| ID | Level | Rule | Verify |
|---|---|---|---|
| DES-21 | MUST | No generic AI look: no unchanged default component-library styling, decorative purple-blue gradients or glows, emoji used as icons, everything centered, identical icon-card grids, stock 3D illustrations, mixed radii and shadows, random accent colors or filler copy; gradient text, colored glows, radial blobs, orbs and mesh washes; sparkle, wand or robot icons standing for "AI"; skeleton bars or fake terminals as product shots; the template stack (hero, logo bar, 3 icon cards, 3 steps, 3 prices, FAQ, 4-column footer) when the content has another shape; and the opposite failure, an identity-free grey default. Every visual choice traces back to `DESIGN.md` and real content. | Design review against this list; swap test: put a competitor's logo and name in. If layout, palette, type and copy still fit, the direction was not applied |
| DES-22 | SHOULD | Translucent style (if chosen): translucency only for navigation, overlays and floating surfaces, never behind long text. `backdrop-filter` gets an opaque `@supports` fallback, contrast is measured against the worst-case background (A11Y-07), blur ≤ 20 px. | Contrast check; low-end device test |
| DES-46 | SHOULD | [house] Ornament budget: decorative backgrounds (grid, dots, noise, mesh) only when `DESIGN.md` names the motif, and never three or more of glass, mesh, glow, noise and grid in one view. No accent stripe on card edges, no arrow on every button, no pulsing dot without a live state, no card inside a card, no pill above the H1 repeating it, no "New/Beta/AI" badge without a real status. Eyebrows add information the heading lacks; section numbers only where order matters, as a real `<ol>`. | CSS grep (`background-clip: text`, `border-left` on cards, `infinite`); DOM probe for nested cards |
| DES-47 | SHOULD | [house] Real imagery: hero and feature visuals show the real product (screenshot or live UI with real data), a real photo, or nothing; no grey skeleton bars, fake terminals or invented dashboards (CON-21). One image treatment per site (untouched or one shared grade). Feature icons depict what their label names. No look-alike of another named product unless the brief asks for it. | Asset and icon-to-label review |
| DES-48 | SHOULD | Browser-drawn surfaces follow the theme: `color-scheme` on `:root` per theme, `<meta name="theme-color">` with light and dark `media` variants, `::selection` from `color.selection` (text ≥ 4.5:1), `accent-color` and `caret-color` from the accent, `scrollbar-color` from neutrals, and explicit colors on native `<select>`/`<option>`. | Screenshots of selection, checkbox, range, select, scrollbar and date input in both themes |
| DES-08 | SHOULD | Motion has a purpose (feedback, state change, orientation): UI transitions 150–300 ms, large elements ≤ 500 ms; entering elements decelerate (`easing.enter`), leaving elements accelerate (`easing.exit`) and run no longer than their entrance, on-screen moves use `easing.standard`, `linear` only for progress and scroll-linked motion. Movement animates only `transform` and `opacity`; color, border and shadow change only as state changes at ≤ `duration.fast`; never `width`, `height`, `top`/`left`, `filter` or `transition: all`. A new interaction cancels a running animation. Reduced-motion variant per A11Y-26. | Grep `transition: all` and raw `cubic-bezier`; Performance panel; OS setting |
| DES-23 | SHOULD | Micro-animations make the interface feel alive without distracting: hover and press feedback on interactive elements, smooth state changes, reveal on scroll within the entry range or once via IntersectionObserver (≤ 400 ms, stagger ≤ 60 ms); the hidden start state exists only inside the animation or a script-added class, so content stays visible without JavaScript or support. Never animate the LCP element in, no scroll-jacking, no looping motion near text, nothing that delays content or input (PRF-01). Prefer CSS and the Web Animations API; reuse a small set of animated components. | Performance trace; reduced-motion check |
| DES-45 | SHOULD | Motion timing: duration follows the area moved (icon, switch, tooltip `fast`; card, popover, panel `base`; drawer, sheet, full-width `slow`/`large`, never > 500 ms), listed per component in `DESIGN.md`. Hover, press and focus feedback has no delay. A stagger group ends within 500 ms ([house]: ≤ 5 steps, DOM order, mirrored in RTL, exits don't stagger). One focal motion per view; at most one looping decoration, paused off-screen and in hidden tabs; no overshoot or bounce on errors, destructive actions or text. | Computed durations vs. the table; `document.getAnimations()` while scrolling |
| DES-43 | MUST | Animation stack: use the first option that does the job: CSS and the Web Animations API ([`motion.css`](../templates/motion.css)), then AutoAnimate or Motion, then GSAP or Lottie with a reason recorded in the brief. Durations and easings come from the transition tokens; every animation has a `prefers-reduced-motion` variant (A11Y-10); animation JavaScript counts against the JS budget (PRF-04). | Code review; bundle analyzer; reduced-motion check |
| DES-44 | SHOULD | Illustration and animated assets: one illustration style per site from own work or [`reference/assets/`](../reference/assets/README.md), recolored to the tokens. Lottie files load lazily below the fold with a static poster, stay ≤ 150 KB ([house]), and never carry essential information alone (A11Y-06). | Network panel; asset register |
