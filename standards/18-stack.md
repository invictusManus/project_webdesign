# 18 · Reference stack

**Why it matters:** One well-chosen stack, set up the same way every time, makes sites fast, crawlable, accessible and cheap to maintain. Google favors no framework; it rewards what the stack delivers: content in the server HTML, crawlable links and good Core Web Vitals. This stack delivers that by default. Guide: steps 9 and 21–26.

Scope: the default stack for new builds (Node.js, TypeScript, Next.js with React, Tailwind CSS), version policy, rendering, JavaScript budget, SEO and media APIs, Tailwind token setup, components, forms, content and data, multilingual setup, security, toolchain, hosting, third parties. The rest of the handbook stays stack-agnostic. Package list and config: [`templates/stack/`](../templates/stack/README.md).

Last verified: 2026-11

| ID | Level | Rule | Verify |
|---|---|---|---|
| STK-01 | SHOULD | New builds use the reference stack: Node.js LTS, TypeScript in strict mode, Next.js (App Router) with React, Tailwind CSS 4 and pnpm. Another stack is chosen only for a reason recorded in the brief (TEC-07). No 3D or WebGL libraries. | `package.json`; `tsconfig.json` has `"strict": true` |
| STK-02 | MUST | Only supported major versions run (TEC-25); exact versions are locked in the lockfile (SEC-14); dependency updates are automated weekly and ([house]) new majors are adopted within 6 months of release. | Lockfile; update bot config; Node.js release table |
| STK-03 | MUST | Server Components by default. `"use client"` sits on the smallest interactive leaf only. Main content, links, canonical and metadata come in the server HTML (SEO-01, SEO-10). Pages are static unless their data requires otherwise; brochure sites may use static export. | View source with JavaScript off: content, links and meta present |
| STK-04 | MUST | Each route's client JavaScript stays within PRF-04; content is never fetched in the browser when the server can render it. | Build output (first-load JS per route); bundle analyzer |
| STK-05 | MUST | SEO through the framework: the Metadata API sets title, description, canonical, Open Graph and `alternates` (SEO-06, SEO-15, SEO-16, SEO-19); `sitemap.ts` and `robots.ts` generate the files (SEO-03, SEO-07); JSON-LD renders in Server Components (SEO-21); internal links use `<Link>`, never `onClick` routing (SEO-11). | View source; Rich Results Test; crawler |
| STK-06 | MUST | Fonts load through `next/font` (self-hosted, no request to Google; PRF-10, PRF-11, PRV-07). Images use `next/image` with `sizes`, and `priority` only on the LCP image (PRF-06 to PRF-08); remote images are allowlisted in `remotePatterns`. | Network panel: no third-party font requests; Lighthouse image audits |
| STK-07 | MUST | Tailwind's theme is generated from the tokens (`scripts/tokens_to_css.py` → `tailwind-theme.css`) with every default reset, so only token utilities exist (DES-02, DES-11). No arbitrary values for design properties (`bg-[#…]`, `p-[13px]`) and no inline `style` for them. | Grep class names for `-[` (Tailwind still compiles arbitrary values); default classes such as `bg-red-500` generate no CSS |
| STK-08 | SHOULD | Interactive primitives (dialog, menu, popover, tabs, select, tooltip) come from Radix UI, styled with tokens (CMP-01, A11Y-11). Icons are imported one by one from `lucide-react` (DES-42). Animation starts from `motion.css`; the Motion library only for gestures (DES-43). | Component review; bundle analyzer |
| STK-09 | MUST | Forms use React Hook Form with a Zod schema shared by the browser and the Server Action or route handler, which validates again (SEC-10). Every Server Action checks authorization (SEC-11, SEC-34) and runs only from same-origin forms (SEC-12). | Submit invalid data with JavaScript off; call the action as another user |
| STK-10 | SHOULD | The content source fits the editors: Payload (open source, runs inside Next.js, self-hosted) when data must stay owned or in the EU; Sanity when a hosted studio suits non-technical editors; MDX files when only developers edit. CMS rules TEC-19, TEC-34 to TEC-36 and TEC-40 apply. | Decision in the brief |
| STK-11 | SHOULD | A database is added only when the site needs one: Postgres with Drizzle ORM, migrations in Git, credentials in environment variables (TEC-11), and no database access from Client Components. | Code review |
| STK-12 | SHOULD | Multilingual sites use next-intl with the locale in the path (I18N-01) and hreflang through the Metadata API `alternates` (I18N-03). | View source per locale |
| STK-13 | MUST | Security headers and a nonce-based CSP are set in `next.config` headers or `proxy.ts` (SEC-03 to SEC-05); `poweredByHeader: false` (SEC-06); only variables prefixed `NEXT_PUBLIC_` reach the browser, and none of them is a secret. | `curl -I`; grep the client bundle for secrets |
| STK-14 | MUST | CI runs `tsc --noEmit`, Biome lint and format, Vitest, Playwright end-to-end tests with axe, and Lighthouse CI on key templates (QA-03 to QA-05, A11Y-23, PRF-02). | CI configuration; green run on the pull request |
| STK-15 | SHOULD | Hosting per the brief: Vercel for speed and preview deploys per pull request (TEC-09), an EU host when data must stay in the EU (PRV-05), any CDN for static export. | Hosting decision in the brief |
| STK-16 | SHOULD | Third-party scripts load through `@next/third-parties` or `next/script` with `lazyOnload`, only after consent and only if listed in the inventory (PRV-01, PRF-13, TEC-20). | Network panel before and after consent |
