# 03 · UX & conversion

**Why it matters:** UX decides whether visitors find what they need and take the next step. Clear structure, mobile-first layouts and simple, honest forms turn traffic into results. Guide: steps 7 and 13–15.

Detail: `reference/google-search/` notes.

Scope: information architecture, navigation, responsive and mobile-first layout, forms, states, conversion and trust, usability testing, product pages, cart, checkout, listings, on-site search. Accessibility requirements are in [`09-accessibility.md`](09-accessibility.md).

Last verified: 2026-10

| ID | Level | Rule | Verify |
|---|---|---|---|
| UX-01 | MUST | The information architecture comes from `url-map.csv` and user tasks: a shallow hierarchy, one clear parent per page, and labels in the users' own words (validated by tree test, card sort or search data). | Sitemap diagram; test results |
| UX-02 | MUST | Primary navigation has ≤ 7 top-level items in the same position and order on every page and marks the current section. The footer repeats key links, contact and legal pages. | Template review |
| UX-03 | SHOULD | Pages at depth ≥ 2 (house heuristic) show breadcrumbs that follow a typical user path, marked up as `BreadcrumbList` (≥ 2 `ListItem`s with `name`, `position` and `item`; the last `item` may be omitted). | Template review |
| UX-04 | SHOULD | Sites with more than about 50 content pages offer site search. The results URLs are blocked in robots.txt (SEO-03). | Manual |
| UX-05 | MUST | Mobile first: designed and built for 360 px first. No horizontal overflow at 360, 390, 768, 1024 and 1440 px. No function depends on hover. | Viewport screenshots |
| UX-06 | MUST | Each page has one primary call to action. It is visually dominant and repeated after long content; secondary actions stay visually subordinate. | Design review |
| UX-07 | MUST | On key pages, the first screen says what it is, who it is for and the main benefit, and shows the primary call to action, with no scrolling needed. | 360 px and 1440 px screenshot |
| UX-08 | SHOULD | Trust signals sit near decisions: reviews with their source, client logos with permission, certifications, guarantees, real contact details, prices or pricing logic. | Design review |
| UX-09 | MUST | Forms ask only for necessary fields, in a single column, with correct input types and `autocomplete`. Fields validate inline on blur. The submit label names the outcome ("Request quote"). After submitting, the user sees a confirmation with next steps. | Form walkthrough |
| UX-10 | MUST | Every view has defined empty, loading and error states. The 404 page offers search or key links (TEC-05). | State inventory |
| UX-11 | MUST | No dark patterns: fake urgency or scarcity, confirmshaming, pre-checked add-ons, hidden costs, back-button hijacking (SEO-33) or consent nudging (PRV-02). | Design review |
| UX-12 | SHOULD | Contact options (phone, email, form, chat) are visible in a consistent place (A11Y-19), and expected response times are stated. | Template review |
| UX-13 | SHOULD | Before launch, at least 5 target users test the core tasks. Every issue that blocks completing a task is fixed. | Test report |
| UX-14 | SHOULD | Conversion paths (entry page → call to action → form → confirmation) are mapped and instrumented (MSR-08). Funnel drop-off is reviewed monthly. | Funnel report |
| UX-15 | SHOULD | Microcopy: buttons say what happens, error messages say how to fix the problem, and terms come from the glossary in `DESIGN.md`. | Copy review |
| UX-16 | SHOULD | If A/B tests run: enough traffic and a written hypothesis, metric and sample size. Variants carry a canonical to the original (not `noindex`) and use temporary (302) redirects. Googlebot sees the same variants as users (no cloaking, no robots.txt-based serving), and finished tests are removed promptly. | Test plan |
| UX-17 | SHOULD | No full-page overlay or dialog hides content on landing (app install, newsletter, promo): use small banners. Never redirect users to a separate page for consent or input; mandatory gates (age, consent) overlay the content instead. Ads and pop-ups never obstruct or distract from the main content. | Manual check at 360 and 1440 px in a fresh session |

## Commerce and on-site search

| ID | Level | Rule | Verify |
|---|---|---|---|
| UX-18 | MUST | *(shop)* Product page: name, price including VAT with a shipping link, availability, variant selectors and add-to-cart are visible without scrolling on mobile and desktop. Below them: images with zoom, description, specifications (CMP-04), shipping and return summary, and reviews (PSY-12). Choosing a variant updates URL (SEO-49), price, image and availability; unavailable variants are marked, never silently hidden. | Template review at 360 and 1440 px |
| UX-19 | MUST | *(shop)* Shipping costs and delivery time appear on the product page or in the cart before checkout starts. No fee is added at the last step (UX-11, PSY-13, PRV-12). | Test order |
| UX-20 | MUST | *(shop)* Cart: every line shows image, variant, quantity (editable) and price, with a remove control. The cart shows subtotal, shipping, tax and total, survives a new session, and has one primary call to action (checkout). A promo-code field is a collapsed link, not an open field. | Test order; return after 24 h |
| UX-21 | MUST | *(shop)* Checkout: guest checkout (account offered after purchase), a single page or ≤ 5 steps with progress (CMP-19), `autocomplete` and address lookup, billing address = shipping address by default, payment methods common in the target market including wallets, the order summary visible throughout, and edits without data loss (A11Y-18). The final button follows PRV-12. | Test order on mobile and desktop |
| UX-22 | SHOULD | *(shop)* Listings and filters: filters fit the category; on mobile they open in a drawer (CMP-12) with an apply button. Active filters show as removable chips (CMP-05) with the result count; sort options are offered. Listings show price, availability and rating, in 2 columns on mobile. A no-results state suggests removing filters. Facet URLs follow SEO-13. | Category page review per tier |
| UX-23 | MUST | *(shop)* After purchase, a confirmation page and email show order number, items, total, delivery estimate, next steps and contact (PSY-11). | Test order |
| UX-24 | SHOULD | On-site search (where offered) tolerates typos and synonyms, suggests after 2–3 characters, and turns zero results into help: suggestions, popular categories and contact. Zero-result queries are reviewed monthly (MSR-09). Result pages follow SEO-63. | Search test with typos; query report |
